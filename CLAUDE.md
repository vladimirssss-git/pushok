# Пушок — Claude Code Operating Manual

## Project

Браузерная 2D-игра про котёнка Пушка. TypeScript + Phaser 3 + Vite, без бэкенда.
Прогресс игрока — `localStorage`. Деплой — статика на GitHub Pages.

- GitHub: https://github.com/vladimirssss-git/pushok
- Прод: https://vladimirssss-git.github.io/pushok/ (после включения Pages)

## Read order

1. Прочитать `CLAUDE.md` (этот файл).
2. Прочитать `AGENTS.md` — универсальный инженерный контракт.
3. Прочитать базу знаний в Obsidian: `docs/01 Design/Пушок — гейм-дизайн.md`.
4. Проверить git: `git status --short --branch`, `git log --oneline -5`.

## Architecture

```
src/
  main.ts            — точка входа, конфиг Phaser, регистрация сцен
  config/            — константы игры: физика, баланс, размеры (единственный источник чисел)
  scenes/            — Boot, Preload, Menu, Game, UI, GameOver
  entities/          — Pushok (игрок), враги, предметы
  systems/           — движение, сбор предметов, здоровье, сохранение
public/assets/
  sprites/           — PNG-спрайтшиты и атласы
  audio/             — музыка и звуки
  tilemaps/          — Tiled JSON уровней
test/                — vitest, юнит-тесты чистой логики
docs/                — Obsidian vault: дизайн, лор, арт, техника, девлог
```

**Правило единственного источника чисел.** Любая физическая или балансная константа
(скорость, гравитация, урон, длительность анимации, цена) живёт в `src/config/`, а не
инлайном в сцене. Инлайновое число невозможно затюнить и невозможно протестировать —
оно молча расходится с тем, что записано в дизайн-заметке.

**Правило разделения логики и Phaser.** Всё, что можно посчитать без канваса — расчёт
урона, условия победы, прогрессия, экономика — пишется чистыми функциями в
`src/systems/` и покрывается тестами. В `Scene` остаётся только ввод, рендер и склейка.
Логика, зашитая в `update()`, не тестируется и переписывается при каждой смене сцены.

**Правило ассетов.** Ассеты грузятся только в `PreloadScene` по ключам из
`src/config/assets.ts`. Строковый ключ, набранный руками в сцене, ломается молча:
Phaser рисует зелёный квадрат вместо спрайта и не бросает ошибку.

**Правило сохранения.** Схема сейва версионирована (`saveVersion`). Изменил структуру —
добавь миграцию в `src/systems/save.ts`. Без миграции у всех, кто уже играл,
прогресс исчезнет без единой ошибки в консоли.

## Commands

```bash
npm install          # установка зависимостей
npm run dev          # dev-сервер на http://localhost:5173
npm run build        # прод-сборка в dist/
npm run preview      # локальный просмотр прод-сборки
npm run typecheck    # tsc --noEmit
npm run lint         # eslint
npm test             # vitest run
```

## Before coding report

Коротко отчитаться перед началом:
- Ветка
- Задача
- Затронутые модули (`scenes/`, `entities/`, `systems/`, `config/`, assets)
- Файлы, которые изменятся
- Риски (что может сломаться в геймплее)
- Какие тесты запустить
- Какой smoke сделать
- Нужно ли одобрение перед реализацией

## After coding report

- Что изменено
- Коммит (hash)
- Тесты: результат
- Typecheck / build: результат
- Smoke: результат
- Docs updated (Obsidian, `docs/`)
- Деплой: статус
- Риски
- Rollback plan

## Smoke matrix

После любого изменения геймплея проверить руками в `npm run dev`:

- игра стартует без ошибок в консоли;
- Пушок ходит влево/вправо и прыгает;
- столкновение с платформой не проваливается;
- сбор предмета увеличивает счётчик;
- смерть ведёт на экран GameOver, рестарт работает;
- сейв переживает перезагрузку страницы.

## Approval gates

Без явного разрешения не менять:

- core game feel — гравитацию, скорость бега, высоту прыжка (`src/config/physics.ts`);
- схему сейва без миграции;
- художественный стиль и палитру;
- имя и характер главного героя.

Фразы, разрешающие деплой на прод: `катим`, `кати на прод`, `deploy prod`, `ship it`.

## Regression protection

Не ломать:

- управление (стрелки/WASD + пробел) — мышечная память тестировщиков;
- совместимость сейвов;
- размер бандла: `dist/` не должен расти без объяснения;
- работу на мобильном тач-управлении, когда оно появится.

## Assets

- Спрайты — PNG, пиксель-арт, base tile 32×32, `pixelArt: true`, без сглаживания.
- Исходники арта (`.aseprite`, `.psd`) — в `art-src/`, они в `.gitignore`.
  В репозиторий коммитится только экспортированный PNG/JSON.
- Уровни — Tiled, экспорт в JSON, не в `.tmx`.
- Аудио — `.ogg` + `.m4a` для совместимости с Safari.
- Файлы больше 5 МБ в git не коммитить. Нужно больше — заводить Git LFS отдельной задачей.

## Documentation

После любой содержательной задачи:

1. Обновить соответствующую заметку в `docs/` (дизайн, техника или девлог).
2. Добавить запись в `docs/05 Devlog/` при заметном изменении геймплея.
3. Обновить `CLAUDE.md`, если изменилась архитектура, команды или правила.
4. Задача не считается завершённой без документационного pass.

## Obsidian

`docs/` — это vault. Открывать в Obsidian: Open folder as vault → выбрать `docs`.

- Заметки версионируются вместе с кодом, поэтому дизайн-решение и код,
  который его реализует, лежат в одном коммите.
- Ссылки — вики-стиль `[[Заметка]]`. Шаблоны в `99 Templates`.
- Плагины и рабочее состояние Obsidian (`workspace.json`, `.obsidian/plugins/`)
  в git не попадают — см. `.gitignore`.
