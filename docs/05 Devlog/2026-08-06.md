## Погоня собаки

Пользователь: «доделай чтобы собака пробегала и если видит котёнка то
пыталась его догнать (внизу)». До этого собака (см. devlog
[[2026-08-05]]) только патрулировала отрезок пола туда-обратно, не реагируя
на игрока.

**Что добавлено** (`src/systems/patrol.ts`):

- `canSeeTarget(enemyX, targetX, targetY, floorY, rangeX, toleranceY)` — цель
  видна, только если она «внизу» (по Y в пределах `toleranceY` от пола — уступ
  выше этого допуска, собака без прыжка туда не доберётся) и в пределах
  `rangeX` по горизонтали.
- `chaseDirection(enemyX, targetX)` — направление прямо на цель.
- Обе функции чистые, протестированы (`test/patrol.test.ts`, включая кейс
  «видит на полу», «не видит на уступе», «вне дальности»).

`entities/Dog.ts` теперь получает координаты Пушка каждый кадр
(`GameScene.update()` → `dog.update(pushok.x, pushok.y)`) и переключается
между патрулём (`ENEMY.dogSpeed`) и погоней (`ENEMY.dogChaseSpeed`, быстрее —
иначе «пытается догнать» не читается). Во время погони собака может выходить
за патрульные границы (`minX`/`maxX`) и бежать по всей ширине пола — иначе
погоня на глазах утыкалась бы в невидимую стену.

**Числа** (`config/enemy.ts`): `dogChaseSpeed: 140`, `dogDetectionRangeX: 220`,
`dogDetectionToleranceY: 20` — подобраны на глаз, не балансили под реальный
уровень сложности.

**Проверено:** `npm run typecheck`, `npm test` (30/30, `patrol.test.ts` вырос
до 10 тестов), `npm run build`. Живой прогон погони в Browser pane не довёл до
конца — то же ограничение автоматизации, что и вчера (`document.visibilityState:
hidden` рвёт устойчивый held-key ввод, единичные нажатия проходят через
прямой JS keydown-диспатч не всегда). Логика — чистые функции, полностью
покрыта юнит-тестами; Phaser-обвязка (`setVelocityX`) тривиальна.

## Мобильный старт был сломан

Пользователь: «на первом экране с телефона невозможно начать игру, похоже
ждёт нажатия пробела». Так и есть: `MenuScene` и `GameOverScene` слушали
только `keydown-SPACE` — на тач-устройстве без клавиатуры пройти дальше
меню было физически невозможно.

**Фикс:** обе сцены (и новая `VictoryScene`, см. ниже) теперь стартуют по
`ПРОБЕЛ` ИЛИ по тапу/клику (`this.input.once('pointerdown', start)`), с
булевым флагом от двойного срабатывания. Подсказка на экране переключается
на «Тапни, чтобы начать» через уже существующий `TouchControls.isTouchDevice`.
Проверено тапом в Browser pane на мобильном вьюпорте (375×812) — переход в
`GameScene` происходит.

## Убрали колючки, сделали уровни процедурными, добавили выход и победу

Пользователь: «шипы надо убрать, островки расставить рандомно но так чтобы
герой мог до них допрыгивать. Если собака видит героя она начинает его
преследовать в том числе прыгая по стойкам. В самом труднодоступном месте
расположен выход с уровня... После выхода на новый уровень островки
расставлены уже в другом порядке и так 5 уровней после чего игра
заканчивается победой». Подробности решения — в [[Пушок — гейм-дизайн]]
(разделы «Уровни и прогрессия», «Опасности»).

**Ключевое инженерное решение** — генератор уровня (`systems/levelGenerator.ts`)
не изобретает свою физику: он подбирает высоту и зазор каждого следующего
уступа под `isReachableAtGap`/`gapWindowForStepUp` из уже существующего
`systems/jumpGeometry.ts` (та же физика, что была откалибрована для
фиксированной лестницы уровня 1, см. devlog [[2026-08-05]]). `gapWindowForStepUp` —
новая чистая функция: аналитически решает, при каком диапазоне дистанций
прыжок высотой `stepUp` попадёт на уступ (окно, а не одна точка — высота
сначала растёт, потом падает обратно).

**Баг, найденный на глаз, а не тестами:** после первой реализации на
скриншоте уступы стояли почти впритык (зазор 24px < тайла 32px — читается
как один блок) и почти все на одной высоте. Причина — при генерации «шаг
вверх/вниз, потом обрезать по границам экрана» шаг вниз рядом с полом
почти всегда обрезался в нулевой. Фикс: высота уступа сэмплируется сразу из
полного допрыгиваемого диапазона, а не «шаг, потом обрезка».

**Второй баг, найденный стресс-тестом на 300+ сидах, а не курируемым
набором:** уступы иногда перекрывались — зигзаг по X мог вернуться в
X-область более раннего (не соседнего по цепочке) уступа. Фикс — проверка
`tooCloseToAny` идёт по всем уже поставленным уступам, а не только по
предыдущему; при неудаче генератор перебирает сетку высот и обе стороны
по X, прежде чем сдаться.

**Осознанный компромисс:** в редчайшем структурном тупике (уступ прижат к
краю экрана, единственное доступное направление целиком занято более ранним
уступом — воспроизведено на 1 из ~2500 случайных уровней в стресс-тесте)
генератор жертвует гарантией «дистанция в безопасном окне прыжка» ради
гарантии «уступы не пересекаются» — наслоение блоков было явно запрещено
пользователем, а не побочный эффект для минимизации. Тест на отсутствие
перекрытий прогоняется на 300 сидах × 5 уровней (1500+ проверок) и остаётся
в `test/levelGenerator.test.ts`.

**Собака и прыжки:** `Dog` получила гравитацию и коллизию с платформами
(раньше двигалась только по фиксированному Y пола). `systems/patrol.ts`
пополнился `canSeeTargetAnywhere` (видит цель по X и Y, не только на полу —
заменяет прежний `canSeeTarget`) и `shouldJumpToTarget` (та же
`isReachableAtGap`, что и у генератора уровня). Прыгает собака только в
погоне — патруль остаётся по полу, чтобы не усложнять и без того новую
механику.

**Выход и прогрессия:** `TEX.exit` — плейсхолдер-текстура (арта нет),
рисуется в `PreloadScene` так же, как земля. `GameScene` читает номер
уровня из `init(data)`, оверлап с выходом вызывает `completeLevel()` —
либо следующий уровень (`scene.start('Game', {level: level+1, fish, lives})`),
либо, после 5-го, новая `VictoryScene`. Смерть теперь явно рестартит
**текущий уровень** с сохранёнными рыбками (было: всегда уровень 1 — не
проявлялось при одном уровне, стало наблюдаемо при пяти); это соответствует
уже существовавшей записи в кор-лупе «смерть → рестарт уровня, рыбки
сохраняются».

**Грабли смоук-теста в автоматизированном браузере, снова (см. уже
задокументированные вчера, [[2026-08-05]]).** В этот раз хуже: не только
клавиатура — `document.visibilityState: hidden` полностью останавливает
Phaser'овский игровой цикл (`game.loop.frame` не менялся ни разу за секунду
ожидания, ни клики, ни диспатч клавиш ни на что не влияли, включая уже
запущенные переходы сцен). Прямой JS-диспатч событий в этот раз не помог
вообще ни для пойнтера, ни для клавиатуры. **Рабочий обход, новый:** дёрнуть
Phaser вручную в обход RAF — `game.loop.step(performance.now())` несколько
раз подряд из `javascript_tool`. Так подтверждена вся цепочка логики:
прыжок собаки в погоне (`velocity.y` стал `dogJumpVelocity` при вызове
`dog.update()` с приподнятой целью), переход между всеми 5 уровнями с
сохранением рыбок (`completeLevel()` дёрнут вручную 5 раз подряд), победа
(`VictoryScene`, сейв корректно сброшен на `level: 1`), смерть → `GameOver`
с сохранением уровня и рыбок в `localStorage`. Если в следующий раз смоук
через Browser pane зависнет — сразу проверять `game.loop.frame`, а не
`document.visibilityState` (та проверка тоже не гарантирует ничего в этой
версии окружения).

**Проверено:** `npm run typecheck`, `npm run lint`, `npm test` (91/91,
включая новый `test/levelGenerator.test.ts` на 59 тестов и стресс-проверку
на перекрытия), `npm run build`. Полный интерактивный прогон через реальные
клики/клавиши в Browser pane не удался по описанной выше причине
окружения — логика подтверждена юнит-тестами и прямым вызовом методов сцены
через `javascript_tool`, а не визуальным кликом.
