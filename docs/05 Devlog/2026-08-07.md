## Шипы как элемент редактора

Пользователь: «добавь еще в editor опцию добавления шипов». Шипы были
удалены 2026-08-06 по просьбе того же пользователя — поэтому возвращены
принципиально иначе, и это главное решение задачи, а не деталь.

**Что было и почему убрали.** До 2026-08-06 шипы жили константой
`LEVEL_1_SPIKES` и методом `GameScene.spawnHazards()` — опасность,
приколоченная к коду уровня. Подвинуть её мог только тот, кто правит
исходники, поэтому она и мешала.

**Что сделано теперь.** Шипы существуют только как содержимое авторского
уровня: палитра редактора → `LevelData.spikes` → `GameScene` расставляет
их из данных. Процедурный генератор шипы не ставит намеренно — он подбирает
цепочку допрыгиваемых уступов и ничего не знает о том, где опасность будет
честной, а где убьёт без шанса увернуться. Раздавать смерть случайно — не
то же самое, что раздавать её по замыслу.

**Совместимость.** `spikes` — опциональное поле (`spikes?: {x, y}[]`,
читается как `data.spikes ?? []`). Черновики редактора лежат в
`localStorage` сырым JSON без версии и миграций, поэтому обязательное поле
молча сломало бы все уже собранные уровни. Проверено подстановкой
черновика старого формата (без `spikes`) — редактор грузит его без ошибок
в консоли.

**Геометрия.** Шипы, как и выход, рисуются с origin (0.5, 1) и хранят
координату **нижней грани** — то есть снапятся основанием на поверхность:
на верх уступа под курсором или на пол в нижнем ряду. Общий с выходом
`snapBottomToSurface` (бывший `snapExitBottom`), никакой второй копии
логики снапа. Текстура — плейсхолдер кодом, как у земли и выхода:
четыре треугольника в тайл шириной и полтайла высотой.

**Урон** — та же `hurt()`, что и от собаки (`BALANCE.hazardDamage`), без
отдельного правила для шипов: одна опасность — один эффект. Проверка
проходимости шипы игнорирует сознательно: «уровень проходим» отвечает на
вопрос «до выхода можно допрыгать», а не «безопасно ли» — расставить
смертельную полосу поперёк единственного пути редактор позволит, это
инструмент дизайнера, а не нянька.

**Проверено:** `npm run typecheck`, `npm run lint`, `npm test` (110/110),
`npm run build`. В браузере: шипы поставлены из палитры на пол и на верх
уступа, черновик сохранил `spikes: [{x:240,y:328},{x:208,y:256}]` — ровно
по решётке, `y` шипов на уступе совпал с его `topY`; «Играть» показал их
в тех же точках. Урон подтверждён наблюдаемым состоянием: шипы поставлены
на старт Пушка → в пробе `Жизни: 3` стали `2` с тряской камеры.
«Скачать» — перехвачен `Blob`, сгенерированный `customLevels.ts` содержит
`spikes`, подставлен в `src/config/` и прогнан `npm run typecheck`
(компилируется), затем откачен.

**Не проверено:** удаление шипов клавишей Delete. Ветка кода идентична
рыбкам (уже работающей), но нажать Delete из браузерной панели нельзя —
Phaser читает `keyCode`, панель шлёт `keyCode: 0` (см.
[[Пушок — техническая архитектура]], раздел про границы браузерного
смоука).

**Палитра.** Красный `#c94f4f` — новый цвет в проекте, занесён в
[[Пушок — арт-бибель]] как «опасность». Правило: красным в игре не
красится ничего, кроме того, что наносит урон, иначе сигнал размоется.
Туда же выписан арт-долг: земля, уступ, выход и шипы до сих пор
рисуются кодом, и их размеры (шипы — 32×16 с привязкой по низу) должен
сохранить будущий пиксель-арт.
