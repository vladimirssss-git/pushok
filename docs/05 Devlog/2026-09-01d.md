# Девлог 2026-09-01: мобильный тап-маршрут Quest

## Статус

Реализовано, ожидает production-деплой. Источник: пользовательский запрос в
Codex — исправить неработающий переход с кнопки уровня на iPhone 14 Pro Max,
дать Пушку перемещение тапом только по дорожке и мосту и перерисовать экран
поворота телефона. Владелец: пользователь проекта.

## Изменение

- переход Menu → Quest запускается на `pointerdown` и защищён от двойного старта;
- `QUEST_ROUTE` описывает допустимую ломаную по земле и мосту;
- `questPath.ts` проецирует валидный тап на маршрут и двигает героя по его длине;
- нижний UI, вода, воздух и точки дальше 24 логических пикселей от маршрута не
  задают движение;
- тень движется вместе с Пушком, новый валидный тап перенаправляет его;
- портретный оверлей получил фон меню, пергамент, деревянную рамку и CSS-иконку;
- добавлено 5 unit-тестов геометрии маршрута.

## Проверка до деплоя

- `npm test`: 131/131; `typecheck`, `lint`, `build` прошли;
- viewport 932×430 (`?touch`): кнопка уровня открывает Quest с первого нажатия;
- Пушок дошёл от старта до вершины моста по маршруту;
- тап по воде не изменил позицию;
- возврат в Menu и повторный запуск Quest работают;
- viewport 430×932: новый портретный экран виден, canvas перекрыт;
- ошибок и предупреждений приложения в консоли нет.

Ограничение: браузерный smoke использует мышиные события через `?touch` и не
заменяет финальную проверку настоящего касания в Safari на iPhone.

Security-review новых файлов не нашёл XSS, URL/file input, секретов или сетевых
операций. `npm audit` по существующему lockfile по-прежнему сообщает advisories
dev-инструментов Vite/Vitest и транзитивного nanoid; они не входят в статический
runtime GitHub Pages и не появились в этом изменении. Обновление major-версий
Vite/Vitest вынесено за пределы мобильного hotfix.
