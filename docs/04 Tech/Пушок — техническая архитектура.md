# Пушок — техническая архитектура

Родитель: [[Пушок — MOC]]

## Стек

TypeScript + Phaser 3 + Vite. Без бэкенда, прогресс в `localStorage`.
Деплой — статика на GitHub Pages (ручной `workflow_dispatch`).

## Структура

```
src/main.ts       — конфиг Phaser и регистрация сцен
src/config/       — все числа игры
src/scenes/       — Boot → Preload → Menu → Game → GameOver
src/entities/     — Pushok и прочие объекты
src/systems/      — чистая логика: движение, прогрессия, сейв
test/             — vitest на чистую логику
```

## Три правила, которые легко нарушить

1. **Числа только в `src/config/`.** Инлайновая константа в сцене невозможна для
   тюнинга и молча расходится с дизайн-заметкой.
2. **Логика — чистыми функциями в `src/systems/`.** Всё, что зашито в `update()`,
   не тестируется и переписывается при каждой смене сцены.
3. **Ключи ассетов — только из `src/config/assets.ts`.** Опечатка в строковом ключе
   не бросает ошибку: Phaser рисует зелёный квадрат.

## Геометрия уровня

Расстановка платформ не ставится «на глаз». Высота и дальность прыжка выводятся из
`src/config/physics.ts` в `src/systems/jumpGeometry.ts`, координаты уступов лежат в
`src/config/level.ts`, а тест `test/jumpGeometry.test.ts` сверяет одно с другим.

Причина: уступ, поднятый на пару пикселей выше прыжка, не роняет игру и ничего не
пишет в консоль — уровень просто становится непроходимым, и это замечает только
живой игрок. Первая версия уровня 1 наступила ровно на эти грабли: подъём 94 px
при высоте прыжка 78.9 px.

Уровень строится на 70% от предельных значений (`SAFETY_FACTOR`): предел достижим
только при идеальном вводе, и уровень на пределе играется как сломанный.

### Высота и дальность прыжка — недостаточная проверка

`isReachable(stepUp, gap)` проверяет предел высоты и предел дальности **независимо**.
Это не гарантирует проходимость: прыжок на уступ выше исходного уровня — гонка во
времени, а не два отдельных лимита. К моменту, когда игрок горизонтально долетает
до передней грани уступа, он должен УЖЕ быть на нужной высоте — иначе врезается в
торец сбоку (bonk) и падает, даже если по отдельности stepUp ≤ maxJumpHeight и
gap ≤ maxJumpDistance выполняются.

Хуже: Arcade Physics при разрешении коллизии по углу может «поймать» игрока и
поставить его на площадку почти без запаса, задолго до её геометрического левого
края (эмпирически проверено прямым пошаговым прогоном Arcade `World.separate` —
см. devlog 2026-08-05). Это делает реальную худшую дистанцию прыжка на следующий
уступ близкой к полному шагу leftX→leftX, а не к «чистому» зазору между площадками.

Добавлена `isReachableAtGap(stepUp, gapPx)` в `jumpGeometry.ts` — считает высоту,
набранную к моменту прибытия на дистанцию `gapPx`, и сверяет её со stepUp. Уровень 1
теперь проверяется в двух сценариях: прыжок с разбега (лучший случай) и прыжок сразу
после посадки у ближнего края (`worstCaseGap()` в `config/level.ts`, худший случай).

## Мобильный ввод

`src/systems/touchControls.ts` — виртуальный геймпад (две кнопки движения + прыжок),
рисуется Phaser-примитивами без ассетов, включается только когда
`TouchControls.isTouchDevice()` возвращает true. `GameScene` мёржит его состояние с
клавиатурой в `update()`: клавиатура приоритетнее, тач — фоллбэк. Раскладка кнопок —
`src/config/controls.ts`. `main.ts` увеличивает `input.activePointers` до 3 — без
этого Phaser не даст держать «идти» и «прыжок» одновременно (два касания разом).
`index.html` — `touch-action: none`, чтобы тач по канвасу не скроллил и не зумил страницу.

## Сейв

Схема версионирована (`SAVE_VERSION`). Меняешь структуру — пиши миграцию в
`src/systems/save.ts`, иначе у всех, кто уже играл, прогресс исчезнет без ошибки в консоли.

```bash
npm run build
```
